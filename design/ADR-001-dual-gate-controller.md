# ADR-001：双关卡控制器架构（PreGate / PostGate）

- **状态**：已接受
- **日期**：2026-09-30
- **决策人**：A组（待互审签署）

## 背景

v1 方案把独立控制器放在 Skill 执行之后，导致：①未授权目标/攻击请求会先被完整分析再拒绝——浪费算力，且"对未授权目标做过分析"这一事实本身已经发生；②LLM 输出直接进过一层过滤就返回，缺少对"分析过程产物"的约束。

## 决策

控制器拆为两个纯硬编码关卡（不依赖 LLM）：

1. **PreGate（入口，前置到一切分析之前）**
   - P1 白名单：target_id 规范化（trim/小写/去路径分隔）后精确匹配
   - P2 授权声明：新目标注册必须携带
   - P3/P4 意图过滤：三级过滤（见 ADR-002）
   - P5 预算：budget ∈ [1,100]，默认 50，单位=工具+LLM 调用次数
   - P6 会话累积：同 session 被拒 ≥2 次 → 冻结整个 session
2. **PostGate（出口，结果返回前）**
   - Q1 payload 扫描（flag{...}/CTF{...}/可运行脚本特征/大块base64）→ BLOCKED
   - Q2 引用回验：失实引用 → 降级 UNCERTAIN/EVIDENCE_FAILED
   - Q3 绕过内容删除：指令性段落删除，保留其余
   - Q4 置信度复核：输出值必须等于规则计算值
   - Q5 UNCERTAIN 透传：放行 + review_required=true（不 BLOCK）

## 理由

- 拦截前置符合"法律红线"：未授权目标不应被分析，只应被拒绝；
- 出口扫描承认"LLM 输出不可信"这一事实，与入口规则共同构成纵深防御；
- 纯硬编码使边界可测试、可审计、可复现——这是项目"边界不依赖模型自觉"这一核心承诺的落地。

## 后果

- 正面：误授权分析从机制上不可能发生；拦截行为 100% 可复现、可写进验收用例；
- 负面：硬编码规则需要持续维护（L0 模式表、payload 正则），用 audit 日志 + finding_log 支撑迭代；
- 释放的选项：PostGate 规则表外置为配置，便于 O5 Change 演进而无需改代码结构。
