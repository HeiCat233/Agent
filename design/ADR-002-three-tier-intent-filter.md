# ADR-002：三级意图过滤（L0 硬拦截 / L1 学习语境豁免 / L2 LLM 兜底）

- **状态**：已接受（L0/L1）；L2 默认关闭，上线须走 O5 Change
- **日期**：2026-09-30
- **决策人**：A组（L0/L1 模式表初版须由负责人审定签字）

## 背景

v1 用关键词子串匹配：`["攻击","破解","绕过","注入","exploit","payload","exp"]`。
缺陷：
- `"exp" in query` 会命中 expected / experiment / expense；
- "这个APP是怎么**防止**被**破解**的？"是正当学习问题，会被误杀；
- 直接与核心指标"学习用途误判率 ≤5%"冲突——按 v1 设计该指标不可能达标。

## 决策

三级过滤，按序执行：

### L0 硬拦截（命中 → REJECTED / ATTACK_INTENT）
明确的攻击请求模式（正则，初版示例，正式版由负责人审定）：
```
(给我|帮我).{0,6}(写|生成|做).{0,8}(破解|注册机|keygen|exp)
绕过(这个|该|它的)?(校验|验证|登录|签名)
提取(密钥|key|flag)         # 无学习语境修饰时
```

### L1 学习语境豁免（命中敏感词但带学习短语 → 放行，转防御视角框架）
豁免短语：如何防止 / 怎么防 / 原理 / 为什么 / 学习 / 理解 / 分析 / 是什么
例："这个APP是怎么防止被破解的？" → 放行，以防御视角+结构解释作答。

### L2 LLM 兜底（默认关闭）
L0/L1 均不确定的边界 query → 本地 LLM 三分类（攻击/学习/无关），超时或失败
**按 L1 放行并标记 audit=true**（宁可放过交给 PostGate 审，不误伤学习请求）。
管理员定期查 audit 日志补充 L0 规则。上线本身作为 O5 Change 候选提案。

## 配套要求

- 正向 query 测试集 ≥50 条，必须包含：`exp` 出现在 expect/experiment 等正常用法、
  含"破解"的防御性提问等 v1 会误杀的样例；
- 负向 query 测试集 ≥50 条（6 类，见 eval/dataset_plan.md）。

## 后果

- 正面：误判率指标可达标；边界规则显式化、可审定、可回归；
- 负面：L0 模式表需要随 Red Team 发现持续补充；存在"新模式未收录"的窗口期，
  由 PostGate 出口扫描兜底。
