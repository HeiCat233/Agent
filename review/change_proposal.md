# Change 提案（change_proposal.md）—— O5 变化与对抗

> O5 要求：业务理由 + 不变量 + 不做内容 + 恢复方式 + 批准状态。
> 以下为两个候选提案的模板；批准人=负责人（见实施路线图 Phase 6）。

---

## Change-01：三级意图过滤上线 L2（LLM 兜底分类）

- **业务理由**：L0/L1 上线后 audit 日志显示存在双方都不确定的边界 query（EXAMPLE：
  预计一批含俚语/谐音的攻击请求未被 L0 命中），误放行率有改善空间。
- **变更差异**：路由前增加 L2 可选层——本地 LLM 三分类（攻击/学习/无关），
  超时或失败按 L1 放行并标 audit=true。
- **仍须保持的不变量**：
  1. 白名单校验必须执行且在 L2 之前（P1 顺序不变）；
  2. 攻击意图最终拦截责任仍在 L0+PostGate（L2 只做分类，不做拦截决策）；
  3. 置信度阈值不变；
  4. UNCERTAIN 必须透传。
- **不做内容**：不用云端 LLM；不让 L2 有直接 REJECTED 权限（只建议）。
- **恢复方式**：配置开关 `intent_filter.l2_enabled=false` 即回退，无需回滚代码。
- **批准状态**：⬜ 待批准（批准人：＿＿＿ 日期：＿＿＿）

## Change-02：加固 APK 的"尽力分析"

- **业务理由**：用户反馈遇到加固 APK 直接返回"无法分析"太武断。
- **变更差异**：对加固样本先做静态尝试（Manifest/资源/未加固 dex 部分），
  能分析多少分析多少，产出部分结论+明确的 capability 边界说明。
- **仍须保持的不变量**：同 Change-01 四条，另加：不提供脱壳/反加固步骤。
- **不做内容**：脱壳、反加固、动态加载对抗；不保证所有加固 APK 都有产出。
- **恢复方式**：配置开关 `hardened_apk.best_effort=false`。
- **批准状态**：⬜ 待批准

---

## Change-03：LLM 拒答率超阈值时更换官方代码模型（预注册）

- **触发条件**：M11（LLM 拒答率）在正向 query 集实测 >2%（ADR-003 触发器）。
- **变更差异**：在**官方发布**的模型/接口范围内更换（GLM 其他型号 / Qwen /
  DeepSeek 等），重测 M2/M3/M11。
- **不变量**：模型仅限官方发布渠道（不使用第三方修改权重）；
  ai_rules 四条铁律不修改；边界仍在硬编码控制器。
- **恢复方式**：模型名回退至前一配置即可，无需回滚代码。
- **批准状态**：⬜ 预注册（仅当 M11 超阈值时启动评审）
